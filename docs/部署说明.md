# QQ 农场智能助手 —— Linux 部署说明

部署入口只有一个：**项目根目录的 `start.sh`**。
把项目整个目录放到服务器上，执行它就会弹出菜单，选完自动装依赖、构建、启动。

> 旧版 `deploy.sh` 已合并进 `start.sh`，保留 `deploy.sh` 只是做转发兼容，两者等价。

---

## 一、把项目放到服务器

任选一种，**不需要打包/解压 tgz**：

```bash
# 方式 A：git clone（推荐，方便后续 git pull 更新）
git clone <你的仓库地址> /root/qq-farm-bot
cd /root/qq-farm-bot

# 方式 B：本地打包上传
#   在本机把整个项目目录（含 core/ web/ napcat/ docker-compose.yml start.sh）压缩后
#   scp / rsync 到服务器，解压成 /root/qq-farm-bot
```

要求：Linux（amd64 / arm64 均可）、Node.js 20+ 或 Docker 20+。
**想用 QQ 扫码登录就必须有 Docker**（NapCat 只能跑容器）。

---

## 二、一键部署

```bash
cd /root/qq-farm-bot
chmod +x start.sh
./start.sh
```

会看到菜单：

```
QQ 农场智能助手 —— 请选择启动方式

  1) 默认版      仅农场服务（占用少，推荐低配机器）
  2) QQ 登录版    额外启动 NapCat，支持面板内 QQ 扫码登录
  0) 退出

请输入序号 [1]:
```

也可以跳过菜单直接指定：

```bash
./start.sh 1        # 默认版  （等价：./start.sh default）
./start.sh 2        # QQ 登录版（等价：./start.sh qq）
```

### 模式 1：默认版

- 有 Docker → 用 `docker compose` 起 `qq-farm-bot` 容器
- 没有 Docker → 用 Node 直接跑（root 装 systemd 服务，非 root 用 nohup 后台）

### 模式 2：QQ 登录版（NapCat 扫码登录）

在默认版基础上自动完成这些配置，**不用手动改任何文件**：

| 自动做的事 | 说明 |
| --- | --- |
| `NAPCAT_LOGIN_ENABLED=true` | 打开面板里的 QQ 扫码登录入口 |
| `COMPOSE_PROFILES=napcat` | 让 compose 一并启动 NapCat 容器 |
| `NAPCAT_DEVICE_NAME` | 取宿主机 hostname，作为 NapCat 设备名 |
| `NAPCAT_IMAGE` | 按 CPU 架构选：`x86_64` → `v4.18.19`，`arm64` → `latest` |
| `NAPCAT_UID/GID=1000` + 目录属主 | 建 `data/napcat/{config,QQ,auth}` 并 chown，避免容器写不进去 |
| 等待就绪 | 轮询 `data/napcat/auth/token`，出现即打印「NapCat 已就绪」 |

**扫码登录怎么用：**

1. 打开面板 → 账号管理 → 添加账号 → 选择「**QQ 扫码登录**」
2. 用手机 QQ 扫描面板里的二维码并确认
3. NapCat 首次启动要拉镜像，通常 1-3 分钟，脚本会等它就绪

> NapCat WebUI 只监听 `127.0.0.1:6099`，公网打不开是**故意的**（它需要 Token 鉴权）。
> 确实要远程访问就走 SSH 隧道：`ssh -L 6099:127.0.0.1:6099 root@服务器`

切回默认版执行 `./start.sh 1`，脚本会自动把 NapCat 关掉（`NAPCAT_LOGIN_ENABLED=false`、
移除 `COMPOSE_PROFILES`），不会留下孤儿容器配置。

## 三、放行端口

```bash
# firewalld
firewall-cmd --permanent --add-port=3007/tcp && firewall-cmd --reload

# ufw
ufw allow 3007/tcp

# 云服务器（阿里云/腾讯云/华为云…）还需在安全组放行 3007
```

`6099`（NapCat WebUI）只监听本机，**不要**对外放行。

## 四、目录结构（跑起来之后）

```
/root/qq-farm-bot
├── start.sh              # 部署/启动/运维入口
├── deploy.sh             # 兼容转发 -> start.sh
├── docker-compose.yml
├── .env                  # 首次运行自动生成（含随机 admin 密码）
├── core/                 # 后端
├── web/                  # 前端（dist 为构建产物）
├── napcat/               # NapCat 镜像构建物 + 开放授权插件
└── data/                 # ★ 全部业务数据（Docker 模式）
    ├── users.json            用户账号
    ├── cards.json            卡密
    ├── redemptions.json      核销流水
    ├── accounts.json         农场账号与自动化配置
    ├── napcat/               NapCat 配置与 QQ 会话
    └── logs/
```

> Node 直跑模式的数据在 `core/data`，Docker 模式在 `./data`。
> 从 Node 模式切到 Docker 时，`start.sh` 会提示是否把 `core/data` 迁移到 `data`。

## 五、首次使用（多用户与卡密）

1. 用部署时打印的 admin 账号登录（密码也在 `/root/qq-farm-bot/.env` 的 `FARM_ADMIN_PASSWORD`）。
2. **立刻改密码**。
3. 生成卡密：「**管理后台 → 卡密管理**」
   - 加时卡：选「加时卡」→ 填时长（如 3 天）+ 数量 → 生成
   - 额度卡：选「额度卡」→ 填数量（如 +3 个农场账号额度）→ 生成
4. 用户注册：访问 `/login` → 切「注册」→ 用户名密码 + 卡密 → 激活
5. 用户续费：「我的账户」页输入卡密核销

内置管理员默认是**超级管理员**（可改角色、可管理其他管理员），
不想这样可在 `.env` 设 `FARM_BOOTSTRAP_ADMIN_AS_SUPER=false` 并另外配置超管。

## 六、常用运维命令

```bash
cd /root/qq-farm-bot

./start.sh status     # 状态（含 NapCat 是否就绪）
./start.sh logs       # 实时日志
./start.sh restart    # 重启
./start.sh stop       # 停止
./start.sh dev        # 本地开发模式（pnpm dev，前台）

# 底层原生命令
docker compose logs -f --tail=200
systemctl restart qq-farm-bot      # Node + systemd 模式
journalctl -u qq-farm-bot -f
```

改了 `.env` 后**必须 `./start.sh restart`** 才生效。

### 更新到新版本（保留数据）

```bash
cd /root/qq-farm-bot
cp -r data data.bak.$(date +%F)      # 先备份
./start.sh stop

git pull                              # 或重新上传覆盖项目文件（data/ 不要动）

./start.sh                            # 再跑一次，选原来的模式
```

## 七、生产环境建议

### 7.1 Nginx 反向代理 + HTTPS（强烈建议）

```nginx
server {
    listen 443 ssl http2;
    server_name your.domain.com;

    ssl_certificate     /etc/letsencrypt/live/your.domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your.domain.com/privkey.pem;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:3007;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;    # WebSocket（实时日志/状态）
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
}

server {
    listen 80;
    server_name your.domain.com;
    return 301 https://$host$request_uri;
}
```

### 7.2 上线前必改

- [ ] 改掉 `.env` 里的 `FARM_ADMIN_PASSWORD`（部署时随机生成的那个）
- [ ] 面板里改 admin 密码
- [ ] 关闭或限制自助注册：`FARM_ALLOW_REGISTER=false`
- [ ] 配 HTTPS
- [ ] 设 `NAPCAT_WEBUI_HOST=127.0.0.1`（默认已是，别改成 0.0.0.0）

### 7.3 定时备份数据

```bash
# 每天 3 点打包 data 目录，保留 7 天
0 3 * * * cd /root/qq-farm-bot && tar -czf /root/backup/farm-$(date +\%F).tar.gz data && \
  find /root/backup -name 'farm-*.tar.gz' -mtime +7 -delete
```

## 八、常见问题

**Q：选了 2 却提示必须安装 Docker？**
QQ 扫码登录依赖 NapCat 容器，无法用 Node 直跑。装 Docker：
`curl -fsSL https://get.docker.com | sh`，或改用 `./start.sh 1`。

**Q：NapCat 一直不就绪 / 扫码没反应？**

```bash
./start.sh status
docker compose logs napcat --tail=100
```

常见原因：
- 镜像拉取失败（网络）：换 `NAPCAT_IMAGE=mlikiowa/napcat-docker:latest` 后 `./start.sh restart`
- ARM 机器用了 amd64 镜像：脚本已按架构自动选，手动覆盖时别写死 `v4.18.19`
- `data/napcat` 目录属主不对：容器以 uid 1000 运行，脚本已 chown；
  手动改过目录的话补一句 `chown -R 1000:1000 data/napcat`

**Q：以前免登录直接进，现在要登录，正常吗？**
正常。多用户体系启用后 `/api/auto-login` 返回 403。要回到单机免登录，
在 `.env` 设 `FARM_USER_SYSTEM_ENABLED=false` 并重启（公网环境不建议）。

**Q：忘了 admin 密码怎么办？**

> 注意：`.env` 里的 `FARM_ADMIN_PASSWORD` **只对首次启动生效**。
> admin 一旦写入 `data/users.json`，就以库里的哈希为准。

用内置应急脚本：

```bash
# Docker 模式
cd /root/qq-farm-bot
docker compose stop
docker compose run --rm --entrypoint node qq-farm-bot scripts/reset-admin-password.js '<你的新密码>'
docker compose start

# Node 模式
pkill -f 'node .*client.js'
cd core && FARM_DATA_DIR=$PWD/data node scripts/reset-admin-password.js '<你的新密码>' admin
cd .. && ./start.sh 1
```

重置普通用户：`node scripts/reset-admin-password.js 新密码 用户名`

**Q：从 Node 模式迁移数据 / 复用旧数据后，用 .env 打印的新密码登录不上？**

`.env` 里的 `FARM_ADMIN_PASSWORD` **只在 admin 首次被创建时生效**。
如果 `data/users.json` 里已经存在 admin（比如从 `core/data` 迁移过来的旧数据），
库里的旧密码仍然有效，新打印的密码是无效的 —— `start.sh` 部署结束时会检测这种情况
并给出警告，不会默默让你拿新密码碰壁。

解决（二选一）：

```bash
# 方案 A：用旧密码登录（如果记得当初 Node 模式部署时打印的密码）

# 方案 B：重置为新密码
cd /root/qq-farm-bot
docker compose stop qq-farm-bot
docker compose run --rm --entrypoint node qq-farm-bot scripts/reset-admin-password.js '<你的新密码>'
docker compose start
```

提示「用户名或密码错误，剩余尝试次数」是防爆破锁定（5 次/15 分钟），
重置密码后立即就能登录；若已触发锁定等 15 分钟即可。

**Q：admin 登录后在「管理后台」改用户，提示「请求失败」/「权限不足」？**

旧版存在权限死锁，已修复：

- 编辑接口只要请求里带了 `role` 字段且不是 `user`，就要求超级管理员权限，
  而编辑表单每次都会带 `role`，于是管理员连自己的昵称、密码都改不了；
- 内置 `admin` 只是 `admin` 角色，而 `super_admin` 只能靠环境变量额外配置，
  不配置就**永远没人能调整角色**。

现在：角色校验只在角色真的变化时执行（改自己的角色直接拒绝），
内置管理员默认就是超级管理员，启动时会自动把已存在的 `admin` 升级
（日志会打印 `[用户系统] 内置管理员 admin 已升级为超级管理员`）。
前端也会展示后端返回的真实错误原因，不再一律「请求失败，请联系管理员」。

**Q：Docker 构建报 pnpm / 网络错误？**
`core/Dockerfile` 用的镜像源是 `docker.1ms.run/library/node:20-alpine`（国内加速）。
服务器在境外或该源不可用时，把三处 `FROM docker.1ms.run/library/node:20-alpine`
改成 `FROM node:20-alpine` 后重新 `./start.sh`。

**Q：怎么确认多用户体系有没有生效？**

```bash
curl -s http://127.0.0.1:3007/api/login -H 'content-type: application/json' \
  -d '{"username":"admin","password":"错误密码"}'    # 应返回 401
curl http://127.0.0.1:3007/api/auto-login -X POST    # 应返回 403（多用户已启用）
```

**Q：架构是 ARM（如甲骨文 ARM 机）能跑吗？**
能。Dockerfile 用官方 `node:20-alpine` 多架构镜像，NapCat 镜像也提供 arm64，
`start.sh` 会自动选 `mlikiowa/napcat-docker:latest`。
