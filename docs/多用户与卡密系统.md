# 多用户账号与卡密管理体系

> 基于 `xxxscarlxrd404/qq-farm-bot`（主项目）实现，用户/卡密模型参考 `Aoluis1005/qq-farm-bot`。
> 原有自动挂机逻辑（runtime / services / provider）**未做任何改动**，本套体系只叠加在管理面板的
> 认证、授权与农场账号归属层之上。

---

## 1. 设计目标

| 能力 | 说明 |
| --- | --- |
| 注册登录 | 账号密码注册，注册必须绑定一张**加时卡**，卡密面值决定初始有效期 |
| 到期限制 | 到期后在登录时拦截，并在每次带 token 请求时复查，强制登出 |
| 卡密系统 | 生成 / 发放 / 核销 / 禁用 / 作废 / 删除，区分**加时卡**与**额度卡** |
| 多用户账号 | 每个用户独立管理自己的农场账号，独立配置自动化参数与掉线提醒 |
| 管理员后台 | 管理全部用户、有效期、额度、卡密，可查看用户名下所有农场账号与配置 |
| 权限隔离 | 普通用户只能访问自己的数据；管理员拥有全部权限；所有接口做权限校验 |

## 3. 数据存储与表结构

沿用项目既有约定：JSON 文件持久化，落在 `data/` 目录（可用 `FARM_DATA_DIR` 重定向），
写入走 `services/json-db.js` 的**原子写**（临时文件 + rename），避免中断损坏。

### 3.1 `users.json` — 用户表

```jsonc
{
  "version": 1,
  "users": [{
    "id": "u_lz3k1a1b2c",
    "username": "alice",            // 3-32 位字母/数字/下划线，唯一
    "password": "<salt>:<pbkdf2>",  // PBKDF2-SHA512, 100000 iter, 64B，永不明文
    "role": "user",                 // user | admin | super_admin
    "nick": "", "email": "", "phone": "", "remark": "",
    "accountLimit": 2,              // 可添加农场账号数量；-1 = 不限；管理员恒为 -1
    "subscription": {               // 有效期（对外同时以 card 别名输出，兼容旧字段）
      "code": "AB12-CD34-EF56-GH78",// 最近一次核销的卡密
      "description": "3天体验卡",
      "expiresAt": 1760000000000,   // null = 永久或未激活
      "isPermanent": false,
      "enabled": true,              // false = 被管理员禁用（封禁）
      "source": "register",         // register | renew | admin | bootstrap | config
      "activatedAt": 1759000000000,
      "totalAddedMs": 259200000,    // 累计加时（永久卡不计）
      "updatedAt": 1759000000000,
      "owner": "alice"
    },
    "mustChangePassword": false,
    "createdAt": 1759000000000,
    "updatedAt": 1759000000000,
    "createdBy": "register",
    "lastLoginAt": 1759000100000,
    "lastLoginIp": "1.2.3.4"
  }]
}
```

### 3.2 `cards.json` — 卡密表

```jsonc
{
  "version": 1,
  "cards": [{
    "code": "AB12-CD34-EF56-GH78",  // 4 组 x 4 位，字母表剔除 0/O/1/I
    "type": "time",                 // time 加时卡 | quota 额度卡
    "description": "3天体验卡",
    // 时间卡
    "durationValue": 3, "durationUnit": "day", "durationMs": 259200000,
    "days": 3, "isPermanent": false, "value": 3,
    // 额度卡（上面时间字段退化为 value 副本）
    // "value": 5, "days": 5,
    "enabled": true,                // false = 禁用
    "revoked": false,               // true = 作废（不可逆）
    "status": "unused",             // unused | used | disabled | revoked（派生自上面三字段）
    "usedBy": null, "usedAt": null,
    "batchId": "b_lz3k...",         // 批量生成批次
    "createdAt": 1759000000000, "createdBy": "admin",
    "updatedAt": null, "revokedAt": null
  }]
}
```

### 3.3 `card-redemptions.json` — 卡密核销流水

```jsonc
{
  "counter": 12,
  "redemptions": [{
    "id": "12",
    "at": 1759000000000,
    "code": "AB12-CD34-EF56-GH78",
    "cardType": "time",
    "username": "alice",
    "operator": "alice",            // 自助为本人，管理员代操作为管理员名
    "action": "redeem",             // register | redeem | revoke
    "summary": "有效期 +3天",

  }]
}
```

## 6. 关键业务规则

### 6.1 有效期计算

统一由 `computeNextExpiry(currentSubscription, duration, now)` 决定：

1. **永久优先**：本次是永久卡，或账号已是永久 → `expiresAt = null, isPermanent = true`，
   后续任何加时都不改变结果。
2. **未过期**：在剩余有效期上**顺延** → `expiresAt = 原expiresAt + durationMs`。
3. **已过期 / 首次激活**：从当前时间重新起算 → `expiresAt = now + durationMs`。

```
注册时：expiresAt = now + 卡密时长
加时卡：未过期 → expiresAt += Δ ；已过期 → expiresAt = now + Δ
永久卡：expiresAt = null, isPermanent = true
管理员：isPermanent = true（内置管理员永不失效）
```

额度卡**不影响**有效期，只做 `accountLimit += value`（`-1` 表示不限，保持不变）。

### 6.2 卡密核销

`redeemCard(username, code, { operator, allowQuota, allowTime })` 的原子流程：

1. 校验卡密存在 → 未作废 → 未禁用 → 未使用 → 类型匹配（注册只允许加时卡）。
2. 按类型改用户（`expiresAt` 或 `accountLimit`）。
3. 卡密落锁：`usedBy = username`、`usedAt = now`、`status = used`。
4. 写核销流水（含 before/after 快照）。
5. 保存 `users.json` + `cards.json`。

**作废**（`revoke`）只把卡密标记为 `revoked + enabled=false`，**不会回滚**已发生的有效期/额度变更，
并写一条 `action=revoke` 的流水。作废后该卡不可再被核销。

### 6.3 权限与数据隔离

三层校验，缺一不可：

1. **网关层**（`admin.js`）：`/api/*` 默认要求 `x-admin-token`；白名单放行
   `/login`、`/register`、`/card/info/*`、`/public/*`、`/card-claim/*`、`/health` 等。
2. **会话层**（`admin-session-manager.js`）：`requireAdminToken` 每次请求复查
   → 无 token(401) / 已禁用(403) / 已过期(403) / 会话超时(403)，命中即作废 token 并断开 WebSocket。
   管理员与超级管理员豁免有效期检查。
   另有 5 分钟一次的 `cleanupInvalidAdminSessions` 定时清理。
3. **数据层**：
   - 角色校验：`requireAdminRole`（admin/super_admin）、`requireSuperAdminRole`（仅 super_admin）。
   - 越权防护：`getAdminUserMutationError` 阻止普通管理员改动其他管理员账号（超管不受限）。

**角色变更规则**（`POST /api/admin/users/:username/edit`，仅在角色**真的发生变化**时校验，
否则编辑表单每次携带的 `role` 字段会让管理员连自己的昵称/密码都改不了）：

| 场景 | 结果 |
| --- | --- |
| 改自己的角色 | 400「不能修改自己的角色，以免把自己锁在门外」（前端同时禁用该下拉框） |
| 授予 `super_admin` | 仅超级管理员可操作，否则 403 |
| 调整**其他管理员**的角色 | 仅超级管理员可操作，否则 403 |
| 普通用户 ↔ `admin` | 管理员即可操作，成功后额度自动置为不限 |

**内置管理员默认为超级管理员**（`FARM_BOOTSTRAP_ADMIN_AS_SUPER` 默认 `true`）。
否则会出现权限死锁：超管只能靠环境变量额外配置，不配置就没人能改角色、没人能管管理员。
已存在的 `admin` 账号会在服务启动时自动升级为 `super_admin`。
   - 账号归属：`canAccessAccount` / `isAccountOwner` —— 非管理员只能访问
     `owner === 当前用户名` 的农场账号；`getAccessibleAccountIdsFromRequest` 用于批量接口过滤；
     Socket 订阅同样按归属校验。
   - 额度校验：`checkAccountQuota` 在新增农场账号时拦截超限。

### 6.4 登录安全

| 规则 | 默认值 | 环境变量 |
| --- | --- | --- |
| 同一账号连续失败 5 次锁定 15 分钟 | 5 / 15 | `FARM_MAX_LOGIN_ATTEMPTS` / `FARM_LOCKOUT_MINUTES` |
| 同一 IP 1 分钟内失败 10 次锁定 10 分钟 | 10 / 10 | `FARM_IP_MAX_ATTEMPTS` / `FARM_IP_LOCKOUT_MINUTES` |
| 密码强度 | ≥6 位、含两类字符、非弱口令 | - |
| 密码存储 | PBKDF2-SHA512 + 32B salt，登录成功自动升级旧 sha256 | - |
| 会话有效期 | 7 天（普通用户） | `FARM_SESSION_TTL_MS` |

## 7. 配置项说明

全部配置在 `core/src/config/user-system.js`，可用环境变量覆盖。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `FARM_USER_SYSTEM_ENABLED` | `true` | 关闭后退化为单机模式（`auto-login` 可用，不做用户校验） |
| `FARM_ALLOW_REGISTER` | `true` | 是否开放自助注册；关闭后只能由管理员开号 |
| `FARM_ALLOW_PUBLIC_RENEW` | `true` | 是否开放免登录续费（用户名+卡密） |
| `FARM_ALLOW_PUBLIC_RESET_PASSWORD` | `true` | 是否开放卡密找回密码 |
| `FARM_CARD_CLAIM_ENABLED` | `false` | 卡密自助领取（发号机）初始开关 |
| `FARM_DEFAULT_ACCOUNT_LIMIT` | `2` | 新用户默认可添加农场账号数 |
| `FARM_ADMIN_USERNAME` | `admin` | 内置管理员用户名（首次启动自动创建） |
| `FARM_ADMIN_PASSWORD` | `admin123` | 内置管理员初始密码，**部署后务必修改** |
| `FARM_BOOTSTRAP_ADMIN_AS_SUPER` | `true` | 内置管理员是否拥有超级管理员权限；关闭后必须另行配置超管，否则无人能改角色 |
| `FARM_SUPER_ADMIN_USERNAME` | 空 | 额外的超级管理员用户名（走环境变量校验，不落库）；留空则不启用 |
| `FARM_SUPER_ADMIN_PASSWORD` | 空 | 额外超级管理员的密码 |
| `FARM_SESSION_TTL_MS` | `604800000`(7天) | 普通用户会话有效期，0 = 不过期 |
| `FARM_MAX_LOGIN_ATTEMPTS` | `5` | 账号连续失败锁定阈值 |
| `FARM_LOCKOUT_MINUTES` | `15` | 账号锁定时长（分钟） |
| `FARM_IP_RATE_WINDOW_MS` | `60000` | IP 频率窗口 |

| `FARM_IP_LOCKOUT_MINUTES` | `10` | IP 锁定时长（分钟） |

## 8. 使用流程

1. 启动服务 → 自动创建内置管理员（`admin` / `FARM_ADMIN_PASSWORD`）。
2. 管理员登录 → 进入「管理后台 → 卡密管理」生成卡密，例如 3 天加时卡 10 张。
3. 用户打开 `/login` → 切到「注册」→ 填用户名密码 + 卡密 → 注册成功即激活 3 天。
4. 用户登录 → 在「概览」添加农场账号（受额度限制）→ 在「设置」配置自动化参数与掉线提醒。
5. 用户到期 → 登录被拦截 / 使用中会话被强制登出 → 在「我的账户」输入新卡密续费。
6. 管理员可在后台直接改任意用户的有效期、额度、启停状态，或代其核销卡密。

## 10. 兼容性说明

- 旧的 `user.card` 字段保留为 `subscription` 的别名，前端与既有代码无需一次性改造。
- 农场账号归属优先读 `owner`，缺失时回落到既有的 `username`，历史数据无需迁移。
- 既有农场账号配置（`automation` / `intervals` / `plantingStrategy` / `offlineReminder`）
  结构与接口均未变更，只是补上了归属校验与管理员视角。
