# 上游同步指南（保留自己的改动）

本仓库 fork 自 `xxxscarlxrd404/qq-farm-bot`，**上游**指原仓库，**本地/fork**指
`BUGDey/qq-farm-bot`。本文说明如何在跟进上游更新的同时，保住我们自己的改动。

---

## 一、remote 约定

```bash
git remote -v
# origin    https://github.com/BUGDey/qq-farm-bot.git          （自己的 fork，推送到这里）
# upstream  https://github.com/xxxscarlxrd404/qq-farm-bot.git  （上游，只拉取不推送）
```

首次设置：

```bash
git remote rename origin upstream          # 原来的 origin 其实是上游
git remote add origin https://github.com/BUGDey/qq-farm-bot.git
git push -u origin main
```

之后**永远只 push 到 origin，绝不 push 到 upstream**。

## 三、标准同步流程

### 1. 先看上游改了什么（不要无脑合并）

```bash
git fetch upstream
git log --oneline main..upstream/main        # 上游新增了哪些提交
git diff --stat main..upstream/main          # 涉及哪些文件
```

重点看 diff 是否命中上表"我们改过的文件"。

### 2. 本地先干净，并留好退路

```bash
git status                     # 确保工作区干净
git branch backup-$(date +%F)  # 建个备份分支，随时能回滚
```

### 3. 合并

```bash
git merge upstream/main
```

**强烈建议加 `--no-ff`，让"同步上游"这件事在历史里单独可见：**

```bash
git merge --no-ff upstream/main -m "同步上游 xxxscarlxrd404/qq-farm-bot 更新"
```

### 4. 有冲突时

```bash
git status                     # 看冲突文件
# 逐个解决：保留双方改动的语义，不要简单二选一
git add <已解决的文件>
git merge --continue
```

冲突解决原则：

- **我们的功能不能丢**：用户/卡密/权限/部署菜单相关代码必须保留
- **上游的 bug 修复要拿**：同一函数里上游改了 bug，要把它的改动融进我们的版本
- 拿不准就 `git checkout --ours <file>` 保我们的，再手工把上游修复点补回来

放弃重来：`git merge --abort`

### 5. 合并后必须验证

```bash
cd core && node --test                 # 全量测试（当前基线 423/426，3 条为上游既有失败）
cd ../web && pnpm build                # 前端能构建
cd .. && ./start.sh status             # 脚本不报错
```

特别关注：我们的 43 条用户体系测试必须全绿
（`node --test test/user-store.test.js test/admin-multi-user.test.js`）。

### 6. 推送

```bash
git push origin main
```

## 四、避免冲突的两个技巧

### 技巧 1：把配置放进 `.env`，别改代码

我们所有可调项都在 `.env`（`FARM_ADMIN_PASSWORD`、`NAPCAT_*`、`FARM_*`），
`.env` 已被 `.gitignore` 排除，永远不会被上游覆盖，也不会进提交。

### 技巧 2：自己的新功能放新文件

新增能力优先新建文件（如 `admin-card-routes.js`）再在 `admin.js` 里注册一行，
而不是大段改写上游文件 —— 这样上游更新时只有"注册那一行"可能冲突，解决成本极低。

---

## 五、另一种方式：cherry-pick（只取想要的更新）

上游改动很大、不想整包合并时，可以只挑需要的提交：

```bash
git fetch upstream
git log --oneline upstream/main          # 找到想要的提交号
git cherry-pick <commit-hash>            # 只拿这一个
git cherry-pick <hash1>..<hash2>         # 拿一段（不含 hash1）
```

适合"上游重写了大块架构，我们暂时只想拿某个 bug 修复"的场景。

---

## 六、只同步部署脚本相关改动到服务器

服务器上的更新不需要动业务数据：

```bash
cd /root/qq-farm-bot
cp -r data data.bak.$(date +%F)   # 备份数据
./start.sh stop
git pull origin main              # 只更新代码，data/ 不动
./start.sh                        # 再选一次原来的模式
```

## 七、常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `fatal: refusing to merge unrelated histories` | fork 时没带历史 | `git merge upstream/main --allow-unrelated-histories` |
| 合并后 admin 登录不上 | 上游重建了 `user-store.js`，密码哈希格式变了 | `node scripts/reset-admin-password.js 新密码` |
| 合并后页面白屏 | 只合并了后端，前端没重新构建 | `pnpm -C web build`，Docker 模式 `./start.sh`（会重建镜像） |
| `progress.md` 冲突 | 我们已删除该上游文件 | 用 `git rm progress.md` 解决（保留删除） |
| 误推到上游 | remote 搞反了 | `git push -f origin main` 修正自己的，立刻检查上游没被改 |
